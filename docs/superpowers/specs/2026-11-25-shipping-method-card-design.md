# طرح بازسازی کارت روش و هزینه ارسال

## هدف

بخش انتخاب روش ارسال در مرحله «آدرس و ارسال» باید از فرم select و radio ساده به یک کارت واضح و قابل‌اعتماد تبدیل شود؛ مشابه الگوی مرجع تصویری کاربر، با تأکید بر روش منتخب و تفکیک روشن روش پرداخت هزینه ارسال.

## دامنه

- بازطراحی `CarrierSelect` با همان API فعلی `/api/transport?isActive=true`.
- حفظ انتخاب خودکار اولین روش موجود، retry خطای دریافت روش‌ها و مقداردهی `transportId`.
- حفظ دو مقدار فعلی پرداخت: `online` و `on_delivery`.
- نمایش توضیح روش ارسال، وضعیت «انتخاب شده» و راهنمای پرداخت در محل.
- چیدمان موبایل تک‌ستونه، بدون overflow افقی؛ دسکتاپ با فضای متعادل‌تر.

## خارج از دامنه

- تغییر مدل دیتابیس، API حمل‌ونقل، pricing یا checkout action.
- افزودن روش ارسال جدید یا تغییر قوانین انتخاب روش.
- تغییر پرداخت نهایی یا درگاه‌های پرداخت سفارش.

## رویکردهای بررسی‌شده

1. بازسازی مستقیم همین کامپوننت به کارت انتخاب روش و دو کارت پرداخت — انتخاب‌شده؛ کم‌ریسک، سازگار با منطق فعلی و نزدیک به تصویر مرجع.
2. کارت رادیویی مستقل برای هر شرکت حمل — مناسب چند روش، اما در موبایل بلندتر و شلوغ‌تر.
3. بازطراحی کامل مرحله checkout — یکپارچه‌تر، اما خارج از نیاز فعلی و پرریسک‌تر.

## طرح بصری

```text
┌ روش و هزینه ارسال                 ● انتخاب شده ┐
│ روش حمل و وزن بسته را مشخص کنید                 │
│ ┌ پست پیشتاز                         [خودکار] ┐ │
│ └ توضیح روش ارسال                              │
│ زمان پرداخت هزینه ارسال                         │
│ ┌ پرداخت آنلاین ┐       ┌ پرداخت هنگام تحویل ┐ │
│ │ رادیو + توضیح │       │ رادیو + توضیح       │ │
│ └───────────────┘       └─────────────────────┘ │
└─────────────────────────────────────────────────┘
```

- کارت اصلی با border سبز و سطح بسیار روشن برای حفظ ارتباط با هویت طب احمدی.
- وضعیت انتخاب با متن و آیکون، نه فقط رنگ.
- حداقل ارتفاع کنترل‌ها ۴۸px و focus قابل مشاهده.
- متن‌ها اجازه wrap دارند؛ عنوان‌ها truncate نمی‌شوند.
- در حالت loading، skeleton/indicator درون همان کارت می‌ماند؛ در خطا، پیام و retry کنار هم و قابل لمس هستند.
- انیمیشن فقط برای تغییر border/background کارت انتخابی و با `prefers-reduced-motion` سازگار است.

## معیار پذیرش

- با یک روش حمل، روش به‌صورت کارت منتخب نمایش داده شود و select مخفی/غیرضروری نباشد.
- با چند روش حمل، کاربر بتواند روش را با لمس کل کارت تغییر دهد.
- تغییر online/on_delivery همان state قبلی را به‌روز کند و در حالت در محل، توضیح محاسبه قیمت نمایش داده شود.
- در عرض ۳۶۰ تا ۳۹۰ پیکسل هیچ متن یا کارت از viewport خارج نشود.
- تست‌های موجود transport و cart بدون تغییر رفتار قبلی سبز بمانند.
